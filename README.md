# wg.sh

交互式、傻瓜式的 WireGuard 组网脚本（Debian / Ubuntu）。

- 一台**有公网 IP** 的服务器做服务端，其它服务器做客户端连上来，**客户端没有公网 IP（在 NAT 后面）也能用**
- 每台机器**自己生成密钥，私钥不离开本机**；双方只交换公钥，用一段「邀请码」和一段「回复码」复制粘贴完成
- 默认只有隧道地址之间的流量走隧道，**不改默认路由**，不影响服务器原有网络；会自动避开已有的 `wg0`、已占用的网段和端口，并检查输入的网段（只允许 10/8、172.16/12、192.168/16 里的 /24）、端口、公网地址和邀请码是否合法
- 开机自启（`wg-quick@接口`），断线自动重连

## 安装

在每台服务器上：

```bash
curl -fsSL https://raw.githubusercontent.com/DarkJimiHole/wg/main/wg.sh -o wg.sh && sudo bash wg.sh
```

```
wg.sh 1.1.0 - WireGuard 组网
  1) 安装服务端（本机有公网 IP）
  2) 安装客户端（本机有没有公网 IP 都行）
  3) 添加客户端（在服务端上）
  4) 删除客户端（在服务端上）
  5) 查看状态
  6) 卸载
```

## 两台服务器组网

服务器 A 有公网 IP，服务器 B 有没有都行。两边各开一个终端：

| 步骤 | 服务器 A（服务端） | 服务器 B（客户端） |
|---|---|---|
| 1 | `sudo bash wg.sh` → **1 安装服务端**，一路回车（接口、网段、端口、公网 IP 都会自动检测，可修改） | |
| 2 | 提示「现在添加第一个客户端？」→ 回车，显示一行 `WGI1:…` **邀请码** | |
| 3 | | `sudo bash wg.sh` → **2 安装客户端** → 粘贴邀请码，一路回车，显示一行 `WGR1:…` **回复码** |
| 4 | 粘贴回复码 | |
| 5 | 显示「握手成功」 | 显示「握手成功」 |

完成后 A 的隧道地址是 `10.66.66.1`，B 是 `10.66.66.2`（以脚本显示为准），两边互相用隧道地址访问即可。

**别忘了**在 A 的云厂商安全组 / 防火墙放行 **UDP 51820 入站**（脚本会自动处理本机的 ufw / firewalld，云安全组要自己去控制台加）。

- 两台都有公网 IP：任选一台做服务端，选 IP 更稳定的那台。
- 两台都没有公网 IP：WireGuard 无法直连，需要第三台有公网 IP 的服务器做服务端，两台都作为客户端连它（客户端之间默认不互通，只和服务端通）。
- 更多服务器：在 A 上再选 **3 添加客户端**，重复第 2~4 步，地址自动分配 `.3`、`.4`…

## 邀请码 / 回复码里有什么

都是 base64 编码的明文，可以自己解码查看（`echo '…' | sed 's/^WG..://' | base64 -d`）：

| | 内容 |
|---|---|
| 邀请码 `WGI1:` | 服务端公网地址和端口、服务端**公钥**、服务端隧道地址、分配给这个客户端的隧道地址 |
| 回复码 `WGR1:` | 客户端**公钥**、隧道地址、名称 |

都不含私钥，被别人看到也连不上（服务端只接受回复码里那个公钥）。

## 生成的配置

服务端 `/etc/wireguard/wg0.conf`：

```ini
[Interface]
Address = 10.66.66.1/24
ListenPort = 51820
PrivateKey = <服务端私钥>

[Peer]
# name: sniper
PublicKey = <客户端公钥>
AllowedIPs = 10.66.66.2/32
```

客户端 `/etc/wireguard/wg0.conf`：

```ini
[Interface]
Address = 10.66.66.2/32
PrivateKey = <客户端私钥>

[Peer]
PublicKey = <服务端公钥>
Endpoint = <服务端公网IP>:51820
AllowedIPs = 10.66.66.1/32        # 只有发往服务端隧道地址的流量走隧道
PersistentKeepalive = 25          # 客户端主动保持连接，NAT 后面也能被服务端访问
```

文件权限 600，第一行有 `# managed-by: wg.sh` 标记，脚本只管理带这个标记的接口，不会碰你手动配置的 WireGuard。

## 常用命令

```bash
sudo bash wg.sh status            # 查看状态（各客户端最近握手时间）
sudo wg show                      # WireGuard 原生状态
sudo systemctl restart wg-quick@wg0
```

## 排错

| 现象 | 检查 |
|---|---|
| 一直没有握手 | 服务端安全组是否放行 UDP 端口；邀请码里的公网地址是否正确（`status` 里能看到）；服务端是否已粘贴回复码 |
| 提示网段或路由冲突 | 本机已有同网段的地址 / 路由（例如 docker 网桥、家里的 192.168.x.0）：安装服务端时换一个网段，例如 `10.77.77.0/24` |
| 提示网段「落在本机的路由 10.0.0.0/8 里面」 | 常见于云厂商内网：隧道网段会挡住那条大路由里的同号地址，一般没影响，确认后继续；不放心就换 `192.168.x.0/24` |
| 提示内核不支持 WireGuard | OpenVZ / LXC 容器等不支持，需要 KVM 等完整虚拟化的机器 |
| 换了服务端公网 IP | 客户端改 `/etc/wireguard/wg0.conf` 的 `Endpoint` 后 `systemctl restart wg-quick@wg0`，或卸载后重新走一遍流程 |

## 卸载

`sudo bash wg.sh` → **6 卸载**：停止接口、删除配置和密钥、撤销 ufw / firewalld 规则。服务端卸载后，客户端也要各自卸载。
